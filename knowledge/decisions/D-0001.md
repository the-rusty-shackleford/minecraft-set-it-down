# D-0001 — A key of its own sets things down

**The ask.** Rusty sent a README for a mod called Set It Down (2026-10-07): put any item down on any
block face as decoration with sneak + right-click, turn it, tip it, pile it, take it back, armour
as the worn piece. Only the README exists; this mod is built from it.

**The problem with the README's gesture.** It takes sneak + right-click on a block before the held
item's own use. Its own review counts some twenty vanilla interactions that shadows while sneaking:
tilling, stripping, waxing, bone meal, buckets, boats, spawn eggs, item frames and more. In this
pack it also breaks Create's wrench, which dismantles by sneak + right-click: `WrenchItem.useOn`
with `isShiftKeyDown`, checked in `create-1.21.1-6.0.10.jar` on the box. Asked, Rusty chose to let
other uses go first. Then he said the decisive thing: "most if not all things should be able to be
set down in such a way that does not interfere with their other uses. If this means changing the
control scheme to accommodate for that, so be it."

**Why not "other uses first" on sneak + right-click.** The hook would sit after the item's own
`useOn` (a MixinExtras wrap in `ServerPlayerGameMode.useItemOn` and
`MultiPlayerGameMode.performUseItemOn`). It would keep the block uses and Create's wrench, but it
would still take the click before an item's use in the air. Food would never be eaten, nor a bow
drawn or a shield raised, while sneaking at a block in reach. It would also end the client's turn
before the off-hand is tried, so the common pickaxe-and-torches pair would stop placing torches
while sneaking. Some items would then have to be undisplayable, which Rusty did not want.

**Decision.**

- **The Set Down key**, `Y` by default. It was unbound in Rusty's pack instance and in the
  helicopter playtest instance; taken in the pack are B G H J M N O K P R V Z C X, Left Alt and
  Left Control.
  - It is in the game's own conflict context, so it works while sneaking. NeoForge judges a key
    with no modifier as up while Shift is held only in contexts that do not overlap the game's
    own, which is Rotorcraft's D-0003 lesson.
  - Pressed at a block face, it sends the block, the face and the point to the server. The server
    checks them as it checks a click on a block: reach, the point on the block, spawn protection
    and building rights.
  - Pressed at a display, it adds one of the held item to that display's pile.
- **Every item can be set down**, block items included: nothing else claims the key, so nothing
  needs excluding. The README's `allowBlockItems` and its deny-list seed are dropped.
  `#setitdown:undisplayable` ships empty, for a server to fill. A projectile a bag lent out mid-draw
  (`Carried.lent`) is refused, as it is never the player's to place.
- **The mouse is untouched except on a display**, as with an item frame: right-click turns it,
  sneak + right-click tips it, left-click takes. With the crosshair on a display, a click is that
  display's, as it would be an item frame's.

**Verified.** The GameTest `aRightClickOnABlockStillSetsNothingDown` right-clicks blocks with
bread, a stick, a sword and a hoe, sneaking and not, through `ServerPlayerGameMode.useItemOn`.
Nothing is set down, and the hoe tills. The booth presses a real Y, and Y with a real Left Shift,
through XTEST. It also holds a real Shift and right-clicks a block with bread: the player eats.
